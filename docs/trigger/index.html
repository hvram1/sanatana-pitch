What starts the work · the report button on sanatana.in/mahabharata

One button starts every loop.

The Mahābhārata site already has the trigger. A signed-in reader selects words on a verse and taps a button; the report is saved, and an email to errors@sanatanasampatti.in opens. Since 21 September readers have sent 820 reports this way. Today each report is a word and a verse number, and a person works down the list by hand. This proposal extends the button a little, so an agent can send each report to the right loop and tell the reader what became of it.

Agents doread new reports every hour; join duplicates; run the first check for each kind; put the report in the right queue with its evidence; close it when the fix lands; tell the reader.
People decidewhat the report is about, since the reader picks the kind; whether it is a mistake; what the text should say; which ideas the team takes up.

Two things to fix first

  • The report list is public. sanatana.in/mahabharata/mail/report opens without signing in and shows every reporter's name, and their email address too wherever one is stored.
  • "Mark as done" is a plain link that anyone can follow. It needs no sign-in. A search engine crawling the list would follow all 583 links and mark every open report done. Both should sit behind an editor's sign-in, and marking should be a form submission, not a link.
The extended button

One more tap: what kind of problem is it?

The reader still selects words and taps. The popup now asks one question, with the last answer already chosen, so a proofreader working down a parva loses nothing. Every other field is optional.

One report, end to end

Report 818: संदेष्टुमहमि

A real open report, sent on 10 October from Sabhā Parva. Here is what would happen to it with the extended button. Steps 1 and 3 happen today. The rest is the proposal.

  1. 1

    ReaderSelect the word, tap, send happens today

    The reader selects संदेष्टुमहमि in "न त्वां संदेष्टुमहमि भर्तॄन्प्रति शुचिस्मिते". With the extended button they leave "Typing mistake" chosen, and may type what it should read.

  2. 2

    AgentPick up new reports every hour to build

    The intake agent reads the reports added since its last run, through a private feed the site provides. It joins duplicates: the same word in the same verse, from two readers, is one item with two reporters. It also records the verse as it stood when reported, so it can tell later whether the verse has changed.

  3. 3

    AgentRun the first check: the witness check exists today

    The check already flags this word. Both editions disagree with ours, and they also disagree with each other, which is why a person has to choose.

    818Both editions agree we are wrong, and differ on the fix

    Our textसंदेष्टुमहमि
    Critical Editionसंदेष्टुमर्हामि
    Duttसंदेष्टुमर्हासि
    What the reviewer seesThe report, the reader's proposed reading if they gave one, both editions' readings, and a link to the verse. The verse says "I need not instruct you about your husbands", and that needs the first person, अर्हामि. That is the reviewer's call to make, not the agent's.
  4. 4

    AgentPut it in the right queue, marked "reviewed" to build

    The report's status moves from "new" to "reviewed", meaning the first check is done. It joins the reviewers' queue for Sabhā Parva with its evidence attached. A report the witness check cannot help with, such as report 820, ददानि, which no edition contradicts, goes into the same queue marked "no witness".

  5. 5

    Reviewer, then typistDecide, and correct the text happens today, by hand

    The reviewer rules: fix, not a mistake, or leave open. The typist corrects the verse in the text, as they do today.

  6. 6

    AgentClose the report when the fix lands to build

    When a commit to the text changes that verse, the agent marks the report resolved, with the commit and the new reading. A "not a mistake" ruling closes it too, with the reviewer's reason. Nobody has to click "Mark as done", and no report is closed without a reason.

  7. 7

    AgentTell the reader to build

    A "My reports" page shows each of the reader's reports and what became of it. Once a week the reader gets one email: "12 of your reports on Sabhā Parva were corrected this week. Thank you." It is one email a week and not one per report: a single proofreader sent 778.

    ResultThe reader sees their work land. The reports become the test set for the agents' own checks, as the 104 September corrections already are.
What has to change

Four changes on the site, one new agent

The site is a PHP application, in the repository Sriraghunandana92/mahabharata on GitHub. Its developer would make the site changes. The agent lives beside the text, in mbh_src.

WhereChange
The popup views/listing/parva.phpAdd the four kinds, remembering the last one chosen, plus "It should read" and a comment. For "The page isn't working", send the screen width and the browser.
The table passage_reportsNew columns: kind, proposed_text, comment, site, screen, verse_hash, resolved_note, resolved_commit, notified_at. The existing status values stay: new, reviewed, resolved.
A private feed controllers/mail.phpGET mail/reports.json?since=ID and POST mail/updateReport, both requiring a token. This is the agent's only way in.
The list mail/reportBehind an editor's sign-in. "Mark as done" becomes a form submission. Add "My reports" for signed-in readers.
The intake agent mbh_src/qa/intake.pyRuns hourly. It reads the feed, joins duplicates, runs the witness check on the reported verses, sorts by kind, updates the status, and closes reports whose verse a commit has changed.

The site column is there so the same table can take reports from the other sites. The Yajurveda and the Smṛtimuktāphalam are static pages on GitHub Pages, with no sign-in of their own. Their button would post to this same endpoint.

The human stays in control

What the intake agent is never allowed to do

  • Change the text. It writes only to the report table, and only through the feed.
  • Close a report without a reason. Resolved means a commit changed the verse, or a person ruled "not a mistake".
  • Re-classify what the reader said. It may add "this looks like the Bhāvadīpa", but the reader's kind stays on the record.
  • Show a reader's name or email publicly, or credit them anywhere without their consent.
  • Email a reader more than once a week.

For the team to decide

Questions before building

  • Who has the editor role on the report list, and who reviews the Mahābhārata queue each week?
  • Do readers want to be credited by name for their reports, as the Nāma-Kośa students are? The answer should come from them.
  • Should the email keep opening by default, or only when the reader asks for it? Today it opens on every report, and 778 reports means 778 drafts in one reader's mail client.
  • Which site gets the button next: the Yajurveda review, or the Smṛtimuktāphalam?
