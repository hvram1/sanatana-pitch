How a text on sanatana.in gets corrected · two cases

Agents find the differences. People rule on them.

Every text on the site was typed in by someone, and typing brings mistakes. Agents can find where a text disagrees with something it should match. They cannot tell a typing mistake from a reading the tradition really has. This page follows two real corrections from start to finish, to show where that line falls.

Agents doread the printed pages; find the same verse in other editions; compare; set aside what agrees; lay the rest out for a person; measure how often they were right; apply the rulings and rebuild.
People decidewhether a difference is a mistake or a real reading; which reading goes into the text; what is noted beside it. Nothing on the site changes before that.
1 · Against the printed pageTaittirīya Saṃhitā with Bhaṭṭabhāskara's bhāṣya. We have the scans, so the book itself is the witness. 2 · Against other editionsMahābhārata, Mahāprasthānika Parva. We have no scans, so two other editions are the witnesses.
Case 1 · Yajurveda

The printed page is the authority. A vidvān reads it.

The bhāṣya on yajurveda.sanatana.in was built from a typed file, a Word document someone keyed in from the Mysore edition. Nobody has checked that file against the book. This case follows one printed page, Volume I page 66, through the checking. The page shows four kinds of mistake, and each one needs a different fix. One of them must not be "fixed" at all.

Where it starts

A bare number, and a file nobody has checked

The printed book puts a small raised number on a word of the mantra, and the same number at the head of the bhāṣya paragraph that explains it. The typed file kept the paragraph's number and lost the mantra's. So a reader on the site sees a paragraph opening with "1" and nothing in the mantra that it points to.

Fixing that means going back to the print. Once someone is checking the print anyway, every other difference between the print and the typed file comes to light too. Here is the page.

¹The numbers on the mantra. ¹ sits on भुवनमसि, ² on जुह्वेहि, ³ on उपभृदेहि, ⁴ on अग्नाविष्णू. Each one points to the bhāṣya paragraph with the same number. The typed file has lost all four.
aThe typed file has a typo. The print reads दक्षिणेन. The typed file has दक्षिणणेन.
bThe reading agent misread a letter. This is on the next page, p.67: the print reads आघार, and the agent read ध for घ.
cThe book records another reading. The print reads जुहूप्रभृतौ, marked with a star. The footnote below says two manuscripts, ख and ग, read जुहूमुपभृतं वा. The reading agent wrote जुहूपभृतौ, the form a reader might expect, and so quietly "corrected" the book.
dA footnote read wrongly. On p.67, a footnote gives a manuscript reading and, beside it, the editor's own guess. The agent read both as the same word, and the difference vanished.

Mysore edition, Vol. I pp.66–67, TS 1.1.12. The boxes are drawn by us. The page is shown here as the vidvān sees it.

What happens next

Seven steps, two of them decided by people

Round markers are work an agent does by itself. Diamonds are where the work stops and waits for a person. Each step is marked with where it stands today.

  1. 1

    AgentTake on the whole volume, not one paragraph done

    The bare "1" is not a one-off. Every anuvāka the typed file covers has the same problem. So the agent opens one job for the printed volumes the typed file came from: Volumes I to III, Kāṇḍa 1 to 2.2. It first reads the running head of every page, "[का. १. प्र. १." and "अनु. १२.]", so it knows which anuvāka each page belongs to.

    Result1,205 pages, each tied to its kāṇḍa, praśna and anuvāka. On the way it found 13 places where the praśna changes mid-volume, and 38 pages that were six anuvākas out, because the book prints two numbers on them.
  2. 2

    AgentRead every page, asking only narrow questions done

    The reading agent sees the page together with the clean mantra text, and is asked only three things. Which number sits on which word? What do the footnotes say? What are the first few words of each bhāṣya paragraph? It is not asked to retype the page, so it has less room to invent.

    ResultFor page 66: four numbers on four mantra words, two footnotes, four paragraph openings. Across the three volumes: 1,763 numbers, 1,392 footnotes, 1,501 paragraph openings.

    Why read every page, and not only where something looks wrong: most of what the typed file says is right, and the only way to show that is to check it against the print. Reading everything lets the vidvān skip what is confirmed and look only at the rest.

  3. 3

    AgentCompare three witnesses, and sort done

    For each item there are up to three witnesses: what the reading agent saw on the page, what the typed file says, and what the bhāṣya says about itself (a paragraph names the words it explains, so ¹ "…भुवनमिति" must belong on भुवनमसि). Where they agree, or the agent's checks leave no doubt, the item is settled. Where they do not, it goes to the vidvān. The agent does not pick a winner.

    What was comparedSettled without the vidvānTo the vidvānSet aside for now
    Numbers on mantra words1,310392 + 61 sample
    Paragraph openings, print against typed file1,05936874 that match no paragraph
    Footnotes434958 source references, such as "ब्रा. ३-३-७", to be linked later

    The sample: one in twenty of the items that agree is shown to the vidvān anyway, so we learn whether "all agree" can be trusted.

  4. 4

    Team memberCheck a sample by eye before the vidvān sees anything done

    A vidvān's hours are the scarcest thing in the project. Before any of them are spent, a member of the team goes through 50 pages by eye against the print, to see whether the agent's sorting holds up.

    ResultOf 40 numbers the agent placed from the page alone, 39 were right. The check also found 54 pages that had been read with the wrong anuvāka's text alongside. Their items go to the vidvān marked "read again", and those pages go into the next reading.
  5. 5

    AgentLay each question out beside the print done

    The agent builds three review pages for each praśna: numbers, footnotes and openings. Each item shows the printed page itself, with the footnote band cut out and enlarged where that helps, so the vidvān checks against the book rather than against us. The differing letters are marked in both readings.

    The vidvān's openings page · Vol. I p.66, paragraph 2

  6. 6

    VidvānRule on each difference, against the print waiting on the vidvān

    This is the step that cannot be handed to an agent. The four cases on pages 66 and 67 each call for a different ruling.

    aThe typed file is wrong p.66 ¶2

    Printed pageदक्षिणेन
    Typed fileदक्षिणणेन
    Reading agentदक्षिणेन
    Ruling"The print differs from the docx." The site takes the printed reading. The typed file is not edited: the correction is a separate entry that says what changed, why, and who ruled.

    bThe reading agent is wrong p.67 ¶6

    Printed pageआघारमाघारयति
    Typed fileआघारमाघारयति
    Reading agentआधारमाघारयति
    Ruling"Docx is right." Nothing changes on the site. The agent's misreading is counted, which tells us how far to trust it next time.

    cThe book records another reading p.66 ¶1 and its footnote

    Printed pageजुहूप्रभृतौ *
    Footnote* ख. ग—जुहूमुपभृतं वा.
    Typed fileजुहूप्रभृतौ (no footnote)
    Reading agentजुहूपभृतौ
    What the vidvān is askedThe print and the typed file agree. The agent wrote what the word "ought" to be (the two ladles, juhū and upabhṛt) and the editor recorded that two manuscripts read it another way. The vidvān decides whether प्र is a misprint. Either way, the edition's reading stays as printed, a misprint is recorded as the vidvān's note, and the manuscript reading is shown with the word. An agent's guess is never written into the text.

    dA variant reading, misread p.67 footnote *

    Printed page* ग—अध्वकर्तृकः. [ … ? ]
    Typed fileThe footnote is not there at all
    Reading agentग—अध्वर्तकः. [अध्वर्तकः ?]
    Ruling"Correct the reading," typed in as printed. Manuscript ग reads one word, and the editor adds his own guess in brackets. The agent read both as the same word, so the variant disappeared. The vidvān restores it, and it is shown on the site as the book prints it.
    Where this standsThe review of Kāṇḍa 1 to 2.2 is live for the vidvān. The rulings come back as one file, which is saved with the corrections.
  7. 7

    AgentApply the rulings and rebuild the site built for Sāyaṇa; next for these

    The agent turns each ruling into a correction entry, rebuilds the bhāṣya from the typed file plus the corrections, and republishes the site. On TS 1.1.12, the word भुवनमसि becomes a link to paragraph ¹, paragraph ² reads दक्षिणेन, and जुहूप्रभृतौ carries a small mark that opens the manuscript reading.

    The rebuild refuses a correction that does not fit. If the words it quotes are not found exactly once, or the place it moves text to is not empty, it stops and says why.

    ResultThe typed file stays as received. Anyone can see the text as it came in, every change made to it, the evidence for each change, and who ruled.
The same loop catches bigger faults

When whole commentaries look missing

The same steps fixed the other bhāṣya on the site, Sāyaṇa's, which has no scans. There the agent compares the typed file with Sāyaṇa's own headings and closing lines, and with the mantras each block quotes. Some anuvākas looked empty. Most of them were not.

Twelve commented as oneTS 2.2.2 to 2.2.12 had no commentary. Sāyaṇa's heading says "तत्र प्रथमादिद्वादशान्ता अनुवाकाः": one commentary for the 1st to the 12th. Now each of the twelve points to that one block, instead of showing as missing.Evidence cited in the entry: his heading and his closing line, प्रथमादिद्वादशान्ता अनुवाकाः ।। १-१२ ।।
One anuvāka hidden inside another6.4.3 was empty, and 6.4.2 was twice the usual length. Partway through, the passages it quotes switch from 6.4.2's mantras to 6.4.3's, and its references change from अ. २ to अ. ३. The block is cut there, and the rest goes to 6.4.3.Cut at अत्रोपावहरेदिति विधिं सूचयन्, his lead-in to the first 6.4.3 quotation.
"Not in our materials" against "not commented"An empty place is never simply called missing. Either our materials lack text the commentator wrote, or the commentator says he does not comment there, as the Mysore print's footnote says of Bhaṭṭabhāskara on 1.4.32–36. The site says which.Two separate labels in the data, so neither is mistaken for the other.
Case 2 · Mahābhārata

No scan to check against. Two editions stand in for it.

The Mahābhārata on sanatana.in is typed from the text Nīlakaṇṭha commented on, with his Bhāvadīpa, and there are no page scans to check it against. Two other editions are available: the Critical Edition from the Bhandarkar Oriental Research Institute in Pune, and M.N. Dutt's text and translation. Neither one is our text, so a difference is not proof of a mistake. This case follows one chapter, Mahāprasthānika Parva 3, where Yudhiṣṭhira will not enter heaven without the dog.

Where it starts

"To eat" where the verse means "to abandon"

Indra tells Yudhiṣṭhira to leave the dog behind. Yudhiṣṭhira answers that he will never abandon one who is frightened and devoted to him: that is his vow. This is the verse as the site had it until 27 September 2026.

Mahāprasthānika Parva 3.12 · as it was typed

भीतं भक्तं नान्यदस्तीति चार्त प्राप्तं क्षीणं रक्षणे प्राणलिप्सुम्।
प्राणत्यागादप्यहं नैव भोक्तुं यतेयं वै नित्यमेतद्ब्रुतं मे॥१२॥

"…even at the cost of my life I will never try to eat him: this is my constant vow."

भोक्तुं means "to eat". The sense needs मोक्तुं, "to abandon". ब्रुतं should be व्रतं, "vow", and चार्त should be चार्तं. These three slips were among the errors sent in to the typing team, who corrected them by hand.

What happens next

Seven steps, two of them decided by people

Here the agent's job is to find mistakes like this one before a reader has to, and to point the typing team at them.

  1. 1

    Readers and typistsErrors are reported and corrected by hand running today

    Readers on sanatana.in report a verse that looks wrong. The typing team checks it and corrects the text. Between July and September 2026 they made 104 corrections to the verses, mostly from errors sent in, verse 3.12 among them.

    Result104 corrections, each one now a known mistake. They also become a test for the agent: a good check would have caught them before anyone reported them.
  2. 2

    AgentFind the same verse in two other editions done

    The three texts number their verses differently, so the agent finds each verse by its words, never by its number. Our 3.12 is Dutt's 310.11. The Critical Edition has no such verse at all: it goes from Yudhiṣṭhira's verse 11 straight to Indra's reply.

    ResultVerse 3.12 has one witness, Dutt. The Critical Edition leaves it out, which is a fact about that edition, not a fault in ours.
  3. 3

    AgentFlag only where both editions agree against us done

    The Critical Edition differs from our recension on thousands of words, and those are real variant readings. So one edition differing proves nothing. The agent raises a firm flag only when both editions read the same word, they differ from ours by a letter or two, and the difference is not a spelling convention. Conventions such as सन्निधौ for संनिधौ, कर्म्म for कर्म, or दत्त्वा for दत्वा are never flagged.

    FlagWhenRaised across the 18 parvas
    Both editionsBoth read the same word, against ours5,468
    One editionOne differs, and the other has no matching verse5,466
    Not flaggedOne edition reads as ours. That is a variant, not a typo
  4. 4

    AgentTest itself on mistakes we already know done

    Before anyone's time is spent, the agent runs its check on the text as it stood in July and compares the result with the 104 corrections the typists made since.

    Of the 104 known correctionsVerses
    Caught, both editions agreeing48
    …with the editions' reading exactly the typist's fix46
    Caught, one edition only (verse 3.12 is one of these)14
    Missed42

    So the check finds about six in ten of the mistakes readers find, and it does not replace them. The misses include plain typos such as भामसेनो for भीमसेनो, so the check still has room to improve.

  5. 5

    AgentLay each flag out for a reviewer done

    The agent builds a review page: our text, the editions' reading, and which edition says what. There is one shared online page, and one file per parva for reviewers who work offline on a phone. An offline reviewer's decisions are sent back as a file through the phone's share menu.

    The review page · Mahāprasthānika Parva 3.11 · open today

    Both editionsनाद्यत्यक्ष्याम्येनं
    FixNot a mistakeLeave open

    A real open flag, from the verse just before 3.12. The buttons stand for the three decisions the page records.

  6. 6

    ReviewerDecide each flag, one verse at a time waiting on reviewers

    The two flags in this chapter show why a person still has to read.

    3.11Both editions agree against us

    Our textत्यक्ष्यामेनं
    Critical Editionत्यक्ष्याम्येनं
    Duttत्यक्ष्याम्येनं
    What the reviewer decidesत्यक्ष्याम्येनं, "I will abandon him", is the form the grammar needs. Two editions that share a reading against ours are rarely both wrong. This one is probably a fix, but a reviewer confirms it before anything changes.

    3.12Only one witness, and it has its own slip fixed by hand on 27 September

    Our text, beforeचार्त … भोक्तुं … ब्रुतं
    Critical Editionhas no such verse
    Duttचात … मोक्तुं … व्रतं
    What the reviewer decidesDutt is right on two words and has a slip of its own on the third: चात for चार्तं. A single edition can be wrong, so the agent marks this kind of flag as weaker and leaves the reading to a person. The fix that went in reads चार्तं, मोक्तुं and व्रतं: two words as Dutt has them, and one where Dutt is wrong too.
  7. 7

    AgentApply the decisions, one parva at a time next to build

    Today the typists apply corrections by hand. The next piece gathers the reviewers' decisions and shows where two reviewers disagree, so a person can settle it. It then applies the agreed fixes to the text, one commit for each parva, so every change can be traced to who decided it.

    ResultA finding stays settled once decided. It comes back only if the verse it was about is changed again.
The human stays in control

What the agents are never allowed to do

For both texts.

  • Treat another edition as the original. The Critical Edition leaves out verses our recension has, and differs on thousands of words. Those are readings of the tradition, not errors in ours. A verse it lacks is never marked "not in the original".
  • Change the text to what it "should" say. The printed edition is the authority. A suspected misprint becomes the vidvān's note, never a silent change.
  • Treat a variant reading as a mistake. When the editor records what the manuscripts read, that reading is kept and shown with the word.
  • Choose between two readings. Every opening where the print and the typed file differ goes to the vidvān: 368 of 368. Every Mahābhārata flag goes to a reviewer, even when both editions agree.
  • Correct silently. In the Yajurveda, corrections are separate entries, each with its evidence, and the typed file stays as received. In the Mahābhārata, every fix is a commit that says who decided it.
  • Call something missing without saying why. Lost from our materials, commented together with its neighbours, or never commented on are three different things.
  • Spend the vidvān's time on an unchecked batch. A person checks a sample by eye first.
How we will know it works

What to measure as the rulings come back

Vidvān minutes per printed pageThe main measure. It sets the pace for the remaining volumes, and for the Brāhmaṇa and Āraṇyaka after them.
Who was right when they differedThe print against the typed file, and the reading agent against both. This tells us which differences could later be settled with less of the vidvān's time.
Whether "all agree" holdsHow often the vidvān overturns an item from the one-in-twenty sample. If that ever happens, the sample grows.
Mahābhārata: caught before a readerOf the mistakes readers report, the share the check had already flagged. Six in ten so far, on 104 known corrections.
Mahābhārata: flags that were wrongHow often a reviewer says "not a mistake", for both-edition flags and one-edition flags separately. This shows which kind deserves a reviewer's time first.
Reviewers who agreeWhere two reviewers decide the same flag, how often they agree. Disagreements go to a person to settle.
For the team to decide

Questions before going further

  • The vidvān's rulings are kept in one browser until they are downloaded. Should they be saved somewhere shared instead, so they follow the vidvān to another device and nothing is lost?
  • Only the opening words of each paragraph have been compared, 7.9% of the bhāṣya's letters. A full comparison needs a paid full-text reading of every page. Is it worth it once we know how often the openings differ?
  • The Brāhmaṇa and the Āraṇyaka have no typed file, so the comparison there would be between two separate readings of the same pages. Who checks those, and how many items will that put in front of the vidvān?
  • How is the vidvān credited on the site for each ruling, and do they want to be named?
  • Mahābhārata: there are 10,934 open flags across the 18 parvas. Should reviewers start with the both-edition flags, or with the parvas readers report most?
  • Mahābhārata: the check sees nothing in the Bhāvadīpa, which neither edition carries, or in the Harivaṃśa, which neither covers. What stands in for a witness there?
Appendix · for the engineers

How it is built

Yajurveda

The pipeline lives in dharmasastra-gcp/complete_pipeline_yajurveda. Where it stood on 15 October 2026 is in docs/TS_review_handoff_2026-10-15.md, and that note wins where it and this page differ.

  • Page map. stage1_ocr/scan_headers.py reads the running head of every page, 25 heads to a call, and carries the anuvāka forward. It covers 3,869 text pages across ten volumes. Kāṇḍa 4 (Vols. VI–VII) has no scans.
  • Reading. stage1_ocr/scan_marks.py sends each page with its anuvāka's clean text to gemini-3.5-flash in Gemini Batch mode, one job per volume. Batch mode is half the price, has no rate limits, and every page is read once. Each answer is checked: the word must exist in the clean text, numbers must run in order, and each number may occur once per anuvāka.
  • The bhāṣya's own words. stage2_analysis/pratika_anchor.py places a number from the words its paragraph names. It placed 90% of them; by chance alone it would place 7%. Grades: firm, ordered, weak. A short pratīka that occurs twice is graded ordered, never firm, because in the pilot the scan was right both times the two disagreed.
  • Review pages. review_queue, review_page, review_footnotes and review_openings build a static site for each praśna, about 250 KB each. It is served on GitHub Pages under yajurveda.sanatana.in/review/TS/. Decisions are kept in the browser under one key and downloaded as decisions_TS_<date>.json.
  • Corrections. stage4_integration/ts_bhashya.py regenerates the site's bhāṣya fields from the typed file and data/corrections/TS/<commentator>.json. The entry types are joint, drop_text, move_text and split_text, and each one carries evidence. Regenerating with no new corrections changes nothing.

Mahābhārata

  • The witness check. mbh_src/qa/witness_check.py joins each verse of xml/NN.xml to the Critical Edition (BORI, in dharmasastra-gcp/workbench/critical-edition) and to Dutt (mahabharata/mn_dutt_processed.json) by shared words, never by number. It compares word by word and keeps a difference only when it is typo-sized (similarity of 0.75 or more). canon() collapses spelling conventions first.
  • Findings. One record per flag in qa/findings/witness/NN.jsonl, in the shape QA_PROPOSAL.md §3.3 sets out. A both-edition flag has severity review, a one-edition flag info. review.tsv lists them all.
  • Measuring. --score 228512a runs the check on the text as it was at that commit and counts the corrections made since. --control measures the catch on the site's open verse reports: on 29 September, 111 of 258.
  • Review. qa/witness_report.py builds the shared review page and per-parva offline files. Each decision is fix, no or open, with the reviewer and the time.
